# Usage Guide

## Purpose

M365 NIST Assessment takes technical findings generated by M365-Assess and produces a reporting package focused specifically on:

- NIST SP 800-53 Rev. 5
- NIST Cybersecurity Framework 2.0

## Assessment Flow

    Microsoft 365 / Entra
            |
            v
       M365-Assess
            |
            v
     Technical findings
            |
            v
    M365-Assess control registry
            |
            +----------------------+
            |                      |
            v                      v
    NIST SP 800-53          NIST CSF 2.0
            |                      |
            +----------+-----------+
                       |
                       v
              NIST-only reports

## Run a Fresh Assessment

For v0.1, use the tenant's primary onmicrosoft.com domain.

Example:

    .\Invoke-M365NistAssessment.ps1 `
        -TenantId 'yourtenant.onmicrosoft.com' `
        -Section Identity `
        -UseDeviceCode `
        -OutputFolder './output/nist' `
        -OpenReport

Replace `yourtenant.onmicrosoft.com` with the actual Microsoft 365 tenant domain.

For fresh assessments, v0.1 rejects a tenant GUID because M365-Assess 2.12.0 can encounter an output-path issue after resolving and renaming a GUID-based tenant assessment folder.

## Reprocess an Existing Assessment

An existing M365-Assess result can be processed without reconnecting to Microsoft:

    .\Invoke-M365NistAssessment.ps1 `
        -ExistingAssessmentFolder '/path/to/Assessment_YYYYMMDD_HHMMSS_tenant' `
        -Section Identity `
        -OutputFolder './output/nist' `
        -OpenReport

This is useful when:

- report formatting is being changed
- NIST mappings need to be reviewed
- an existing assessment needs to be regenerated
- Microsoft authentication should not be repeated

## NIST Reporting

The current version produces two dedicated NIST views.

### NIST SP 800-53 Rev. 5

Findings are mapped to applicable SP 800-53 controls and summarized by control family.

Examples include:

- AC — Access Control
- AU — Audit and Accountability
- CM — Configuration Management
- IA — Identification and Authentication
- IR — Incident Response
- SA — System and Services Acquisition
- SC — System and Communications Protection
- SI — System and Information Integrity

### NIST CSF 2.0

Findings are mapped to applicable CSF 2.0 subcategories and grouped by function:

- GV — Govern
- ID — Identify
- PR — Protect
- DE — Detect
- RS — Respond
- RC — Recover

An Identity-only Microsoft 365 assessment may not produce findings for every CSF function.

## Finding Statuses

The reporting layer preserves M365-Assess finding statuses:

- Pass
- Fail
- Warning
- Review
- Info

## Mapped-Check Pass Rate

The HTML report calculates:

    Pass / (Pass + Fail + Warning)

Review and informational states are excluded from this denominator.

The mapped-check pass rate is a technical assessment metric.

It is not a NIST compliance percentage.

## Output Files

A successful assessment package contains:

- NIST-Assessment.html
- NIST-Findings.csv
- NIST-SP800-53-Findings.csv
- NIST-SP800-53-Family-Summary.csv
- NIST-CSF-2.0-Findings.csv
- NIST-CSF-2.0-Function-Summary.csv
- NIST-Compliance-Matrix.xlsx
- assessment-metadata.json

## Sensitive Data

Microsoft 365 assessment output may contain security-sensitive information such as:

- tenant configuration
- role assignments
- identity information
- authentication settings
- Conditional Access configuration
- application registrations
- enterprise applications
- security findings

Do not commit real assessment output to source control.

The repository `.gitignore` excludes the local module directory and generated assessment folders.

## Assessment Boundary

M365 NIST Assessment provides technical Microsoft 365 evidence mapped to NIST references.

A complete organizational NIST assessment requires additional evidence beyond Microsoft 365 configuration, including governance, policies, processes, architecture, interviews, and systems outside the assessed tenant.
