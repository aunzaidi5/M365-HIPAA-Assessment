# M365-NIST-Assessment

A small NIST-focused reporting layer for **M365-Assess**.

It keeps M365-Assess as the read-only Microsoft 365 / Entra collection engine, but the
output generated by this wrapper contains only mappings for:

- **NIST SP 800-53 Rev. 5**
- **NIST Cybersecurity Framework (CSF) 2.0**

It intentionally removes the other compliance-framework columns from the wrapper's final
reporting package.

## Important interpretation boundary

This tool **does not certify NIST compliance**.

M365-Assess evaluates Microsoft 365 technical settings and maps its findings to framework
references. Therefore this wrapper reports things such as:

- finding status: Pass / Fail / Warning / Review
- M365-Assess CheckId
- observed and expected values when available
- remediation
- mapped NIST SP 800-53 control IDs
- mapped NIST CSF 2.0 subcategories

A statement such as `73% NIST compliant` would be inappropriate. The HTML report labels its
numeric status metric as a **mapped-check pass rate**, not a framework compliance percentage.

## Requirements

- PowerShell 7+
- M365-Assess 2.12.0 or newer recommended
- ImportExcel (optional, only for the XLSX matrix)

Install:

```powershell
Install-Module M365-Assess -Scope CurrentUser
Install-Module ImportExcel -Scope CurrentUser
```

## Recommended first test — Identity only

```powershell
cd .\M365-NIST-Assessment

.\Invoke-M365NistAssessment.ps1 `
    -TenantId 'contoso.onmicrosoft.com' `
    -Section Identity `
    -UseDeviceCode `
    -OpenReport
```

## Re-process an assessment you already ran

This is useful for the CDX assessment already produced by M365-Assess because it avoids
querying the tenant again.

```powershell
.\Invoke-M365NistAssessment.ps1 `
    -ExistingAssessmentFolder 'C:\IdentityAssessment\M365-Assessment\Assessment_20260825_133950_m365ds745668' `
    -Section Identity `
    -OpenReport
```

## Broader technical scope

```powershell
.\Invoke-M365NistAssessment.ps1 `
    -TenantId 'contoso.onmicrosoft.com' `
    -Section Identity,Security,Intune `
    -UseDeviceCode
```

## Output

├── Raw-M365-Assess/                   # only when a fresh scan is run
└── NIST_20260829_233000/

    ├── NIST-SP800-53-Findings.csv
    ├── NIST-SP800-53-Family-Summary.csv
    ├── NIST-CSF-2.0-Findings.csv

## Architecture

```text
Microsoft 365 / Entra
        |
        v
M365-Assess collectors
        |
        v
M365-Assess CheckIds + evidence
        |
        v
M365-Assess controls/registry.json
        |
        +-------------------+
        |                   |
        v                   v
nist-800-53            nist-csf
        |                   |
        +---------+---------+
                  |
                  v
          NIST-only package
```

## Why this wrapper does not rewrite M365-Assess

Authentication, Graph collection, Conditional Access evaluation, PIM checks, application
checks, evidence collection and CheckId mapping are the difficult parts. Reusing the upstream
engine reduces unnecessary code and makes future M365-Assess improvements easier to consume.

## Files

- `Invoke-M365NistAssessment.ps1` — orchestration
- `Functions/Get-NistMappedFindings.ps1` — registry + evidence filtering
- `Functions/Export-Nist80053Report.ps1` — SP 800-53 CSV and family summary
- `Functions/Export-NistCsfReport.ps1` — CSF 2.0 CSV and function summary
- `Functions/Export-NistComplianceMatrix.ps1` — XLSX matrix
- `Functions/Export-NistHtmlReport.ps1` — standalone HTML report
- `config.json` — wrapper configuration
- `LICENSE` — MIT license / upstream attribution

registry rather than recreating NIST mappings manually.

## Zero Trust / NIST SP 800-207

This wrapper deliberately does **not** pretend that M365 tenant configuration alone is a full
NIST SP 800-207 Zero Trust Architecture assessment. SP 800-207 architecture and operating-model
evidence should be assessed separately through architecture review, workshops, documentation,
and appropriate Zero Trust assessment tooling.
